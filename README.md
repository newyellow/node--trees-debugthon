# Trees Debugthon

沈伯洋市政 debug 松「把三千棵樹種回來」的第一階段資料探索工具。使用 **Leaflet + OpenStreetMap**，不需要 API 金鑰。各子站使用獨立 HTML 入口，入口架構見 [多子站開發契約](docs/multisite.md)。

## 啟動

需要 Node.js 20.19+ 或 22.12+；更新資料另外需要系統 `curl`。

```sh
npm install
npm run dev
```

開啟首頁入口（預設 http://127.0.0.1:5173/），完整資料探索地圖位於 `/explorer/index.html`，另有 `/workspaces/02/index.html`、`/workspaces/03/index.html` 兩個功能待定的預留頁。首頁不載入地圖或資料。 `public/data` 已附官方資料快照，不需要先更新資料。底圖和選用的 Google Fonts 字型需要網路，字型載入失敗時使用系統字型。

## 使用

- 勾選五個圖層，調整各自透明度，並用行政區篩選。
- 搜尋已勾選圖層的名稱、路段、位置或編號欄位，例如路名、公園名稱或樹種；按 Enter 定位符合的資料。這不是地址地理編碼服務。
- 地圖數字顯示目前視野與篩選條件下的紀錄筆數，跨圖層加總不等於樹木總數。
- 全市視角使用空間網格合併所有點位，不抽樣。點擊圓圈可放大；層級 17 起顯示獨立點位、人行道層級 15 起顯示面域、樹穴層級 18 起顯示面域。完全重疊的紀錄在最大縮放層級可點擊圓圈逐筆查看。
- 點擊獨立點位或面域，查看完整原始屬性；「資料說明」列出來源、快照時間、可繪製與排除筆數。
- 「符合資料」將鏡頭移至符合篩選的所有已載入紀錄；「全市視角」清除行政區與文字篩選。

### 樹木密度模式

切換到「樹木密度」，以固定的 **100／250／500 公尺正方形網格**在前端統計勾選的行道樹與公園樹木。其他圖層會暫時停用，切回「點位與群聚」可繼續查看；行政區與搜尋篩選仍會套用。

網格使用 TWD97 公尺座標並固定原點，完整網格的計數不因平移或縮放而改變。預設邊長 250 公尺（每格 6.25 公頃），可調整網格邊長與密度圖透明度，點擊網格查看總紀錄筆數、各樹木圖層筆數與每公頃密度。

色階由紅（少）→ 黃（中）→ 綠（多），固定以 **0、5、10、20+ 筆／公頃**插值；不隨目前視野最大值重新正規化。不同網格尺寸、行政區或縮放層級仍使用相同密度基準。這是紀錄密度，不是樹冠覆蓋率，未進行跨資料集去重。

只在符合篩選的樹木資料外接矩形內繪製網格（不是行政區邊界或調查覆蓋範圍），其中 0 筆顯示為紅色；外部不著色。0 筆代表沒有符合的資料紀錄，不表示現地沒有樹木，尤其在套用樹種搜尋後，只能解讀為沒有符合該條件的紀錄。尚在載入或載入失敗的圖層不參與統計，介面會提示載入狀態。

## 更新資料

```sh
npm run data:refresh
```

`scripts/prepare-data.mjs` 使用 `curl` 從來源下載，原始檔放在忽略追蹤的 `data/raw/`；輸出 WGS84 GeoJSON 和 `public/data/manifest.json`。資料全部轉換完成後才替換輸出，下載失敗會保留上一份可用地圖快照。更新完成後重新整理網頁；若要發布，重新執行建置。只想重新轉換本機已有原始檔可用 `node scripts/prepare-data.mjs --cached`。


測試涵蓋 TWD97 控制點、無效座標、多層幾何轉換、12 行政區代碼、篩選、聚合不遺漏紀錄，以及全部快照筆數與範圍一致性。

### 依區、依里與人行道輪廓分析

在「樹木密度 → 統計輪廓」切換「依行政區」「依里」「依人行道」。網格模式仍保留。

區里輪廓來自[臺北市民政局里界圖](https://data.taipei/dataset/detail?id=6b17b31d-4e16-495e-95b1-9fd1f47c80d8)，本次下載的 SHP 包含 456 里，採 TWD97 公尺座標，DBF 編碼依 `.cpg` 讀取為 UTF-8。為消除共邊浮點誤差，先取到公分，再用多邊形聯集合併出同一版的 12 區；區界不另混用不同年份來源。`public/data/regions.json` 包含官方輪廓、面積、樹木空間歸屬與來源資訊，約 3 MB。

以多邊形包含判斷將樹木各分配到一個里，再向上彙總至區；邊界上的同一筆紀錄以排序後的里代碼決定唯一歸屬。行道樹 21 筆、公園樹木 27 筆座標未落在官方里界，保留為未歸屬並在介面揭露，不以最近的里強制填入。行政區與文字篩選可搭配使用；區里模式的行政區篩選採空間歸屬，不使用樹木原始行政區欄位。點擊輪廓顯示完整區里筆數、面積與每公頃密度，地圖摘要加總與目前視野相交的完整區里。

行政面積含山地、水域等非道路空間，且資料只涵蓋調查的行道樹與公園樹木。顏色代表紀錄密度，不直接宣稱樹木或樹蔭是否充足。

人行道分析模式在所有縮放層級持續繪製視野內的真實面域，全市視角也會顯示；縮遠時使用較細的描邊，放大後可查看路段細節（也可按「放大至街區查看」）。區里密度同樣不設縮放門檻。人行道在 Web Worker 背景運算，使用 RBush 找鄰近候選樹木，包含：

1. **鄰近樹木數／每 100 公尺**：計算樹木點到人行道多邊形的最短距離，包含多邊形內部與洞；在指定距離內的樹木除以官方路段長度，再乘以 100。沒有有效正長度的路段不推估，使用灰色。
2. **輪廓鄰近率**：沿各外環每約 10 公尺均勻取樣，以每個取樣點代表的輪廓長度加權，計算指定半徑內存在樹木的比例。不是按原始頂點個數統計，也不是中心線或實際樹冠覆蓋率。
3. **探索目標達標比**：`min(每百公尺樹木數 ÷ 數量目標, 輪廓鄰近率 ÷ 鄰近率目標, 1)`，以紅黃綠表示，兩項都達標才呈綠色。可避免大量樹集中一端而把整條路當成充足。

預設距離 10 公尺、每百公尺 10 筆、鄰近率 70%；這些是可調的探索設定，**不是官方標準**。可選距離 5／10／15／20 公尺、數量目標 5／10／20 筆、鄰近率 50／70／90%。點擊路段查看長度、鄰近數、每百公尺數、鄰近率、取樣點數及判讀。

人行道搜尋只篩選路名、起訖等路段資料，行政區只篩選人行道；鄰近樹木保留勾選圖層的全市紀錄，避免跨區邊界截斷鄰樹。同一棵樹可以鄰近多段人行道，路段之間的鄰近樹木筆數不能直接加總成獨立樹木數。尚未判斷道路阻隔、樹冠大小、日照角度、樹木存活及實際可遮蔭性；寬廣或形狀複雜的面域，其輪廓鄰近率也不等同於步行路徑的連續樹蔭。

更新樹木與官方區里分析快照使用 `npm run data:refresh`；只更新邊界及空間歸屬使用 `npm run boundaries:refresh`（需 `curl`、`unzip`）。`node scripts/prepare-regions.mjs --cached` 可用既有 SHP 壓縮檔重建。區里歸屬附帶樹木快照版本，若不一致會停止判讀並提示重建，避免舊歸屬套用新樹木資料。

`npm test` 另涵蓋孔洞與多部件幾何、面積、鄰近距離、取樣長度加權、聚集／均勻樹木的評分差異，以及完整區里資料的筆數守恆。啟動網站後，可用 `node scripts/check-analysis-browser.mjs` 實測新增的輪廓與分析功能。官方 SHP 讀取及合併使用 `shapefile`、`polygon-clipping`。

### 增量繪製與人行道分析快取

平移地圖時，先用 RBush 找到與視野相交的資料，再以固定 ID 比較前後集合：只建立新增的圖形、移除離開的圖形，仍在視野內的 Leaflet 物件與彈窗會保留。網格使用公尺格座標、區里使用行政代碼、人行道與原始面域使用來源紀錄索引；透明度變動只更新樣式。模式切換、搜尋／篩選造成統計改變時，才使相關圖層內容失效。

點位群聚依目前縮放層級的全域固定像素格建立，整個格子的筆數與中心點不因視野邊界切過而改變；每個資料集快取目前縮放／篩選的群聚索引。地圖上的群聚圓圈可能包含格子裡位於視野外的紀錄，摘要筆數仍依實際視野統計。

人行道結果另按樹木圖層及距離／目標設定快取。平移時只把缺少結果的新路段索引送進 Web Worker；已在計算中的索引不重複送出，晚回傳的結果仍存入對應設定供之後回訪。新路段計算期間保留視野內已完成的結果。前端與 Worker 皆限制近期設定快取，避免使用者反覆調整目標造成持續累積。

這裡減少的是應用程式建立／移除繪圖物件及重算分析的成本；Leaflet Canvas 本身仍會因平移或縮放更新畫面。可用 `node scripts/check-incremental-browser.mjs` 實測五種模式的重用、新增、移除及樣式更新，也會檢查實際送往 Worker 的路段索引。

### 正射航照人工對照

左側「底圖對照」提供街道（OpenStreetMap）、正射航照（國土測繪中心）與混合對照。混合模式可調整航照不透明度 0–100%；「顯示資料圖層」可暫時隱藏點位／群聚、面域、密度圖與其彈窗，保留勾選、記憶體資料和統計，方便單看底圖。按「放大查看樹木點位」可進入層級 17。航照保持原色，街道底圖才套用淡色濾鏡。

影像使用[國土測繪中心官方 WMTS](https://maps.nlsc.gov.tw/S09SOA/pro/Wmts_ajax_main.jsp) 的 `PHOTO2`，投影為 EPSG:3857：

```text
https://wmts.nlsc.gov.tw/wmts/PHOTO2/default/GoogleMapsCompatible/{z}/{y}/{x}
```

WMTS 路徑順序是列／行（y/x），與常見 XYZ 位址順序不同。`GoogleMapsCompatible` 是圖磚矩陣名稱，請求送往國土測繪中心，不是 Google Maps API。最大原生縮放層級依官方服務為 19，並不等於影像地面解析度。服務來源與格式經 GetCapabilities 確認，影像署名保留於地圖上。

預設街道模式不請求航照；首次切入才載入目前視野的航照圖磚。純航照模式停止掛載街道底圖，混合模式才同時顯示兩者；切換底圖與透明度不重新下載樹木等資料。每個影像來源依視野正常載入圖磚，不預抓整個城市。影像載入失敗時提供重試與切回街道，資料圖層仍可操作。

此介面尚未取得各區域影像拍攝日期，影像不可視為即時現況；請比較樹木原始調查日期，並考量定位誤差、樹幹與樹冠偏移、修剪、陰影及不同時期的影像。這一版僅作人工疊合對照，尚未做樹冠辨識、NDVI、移除判定或影像衍生指標，也不把圖磚當成可直接自動分析的原始影像。

啟動開發伺服器後執行 `node scripts/check-aerial-browser.mjs`，可驗證實際官方圖磚、疊合、透明度、來源署名、不重抓業務資料、區里疊圖、手機版與圖磚失敗／重試。

航照年度選單提供「最新拼接影像」以及 **2022、2023、2024、2025 年度版**，對應官方 `PHOTO2`、`PHOTO2022`～`PHOTO2025`；目前服務規格尚未列出 `PHOTO2026`。只在選擇該年度後請求目前視野的圖磚，不預載其他年度，也不請求 2022 年以前的年度圖層。切換只更新影像位址，保留地圖位置、縮放、樹木資料、混合不透明度和資料圖層顯示狀態，並同步更新地圖署名中的版本。

年度版是官方更新版本，不是精確拍攝年份；部分區域可能沿用更早影像，兩個年度版也可能在同一位置使用相同照片。介面已提醒參考區域浮水印；尚未提供拍攝日期／時刻選擇。

### 離線影像分析資料

專用目錄為 `data/offline-imagery/`，已完成的影像、來源紀錄、邊界及盤點報告納入 Git；未完成下載與暫存檔仍排除，影像不隨網站發布。執行 `npm run imagery:plan` 會根據現有 12 區實際邊界產生全臺北分析遮罩、2022–2025 年影像需求及第 16–19 層外接矩形容量估算。這是申請準備，尚未取得完整全市影像包；官方離線申請需要本人聯絡資訊、Email 驗證及核准，歷史年度也須另行確認。取得官方包後可用 `imagery:import` 或 `imagery:download` 匯入，支援續傳、格式檢查與 SHA-256 防止重複下載。完整流程與資料限制請見 [離線影像目錄說明](data/offline-imagery/README.md)。

本機 `npm run dev` 另啟用航照圖磚的磁碟快取：只有正在瀏覽的圖磚會在缺少時向官方取得，之後從 `data/offline-imagery/tiles/` 讀取，重啟仍保留。各年度、層級分開保存，並保留原始 JPEG/PNG 及來源座標紀錄。`IMAGERY_OFFLINE=1 npm run dev` 可禁止航照缺圖時連線；此設定不影響 OSM 街道底圖。正式建置直接使用官方圖源，不發布本機影像。這不是完整全市下載，也不變更來源使用條件。

### 樹種分布、組成與多樣性（待審閱，未發布）

新增「樹種分析」模式。其行道樹／公園樹木來源勾選**獨立於點位、密度模式**，離開後不改原圖層設定。

- **空間分布**：搜尋樹種選單、勾選多個來源名稱；未勾選表示全部。選單搜尋只縮小選單；上方全站文字搜尋及行政區篩選仍作用。獨立點與同類別群聚使用由常見名稱固定對比色及其他名稱雜湊得到的穩定色；混合類別群聚為灰藍，缺失／枯木為灰。少數名稱可能有近似色，請搭配文字圖例，選取少數樹種或放大辨識。全覽使用固定網格群聚，細節沿用 Canvas 點，不建立每棵樹的 DOM。群聚筆數可由提示查看，點擊放大。
- **區／里組成**：使用官方里歸屬，向上彙整 12 區；保留 456 里含零筆單位。點擊輪廓或單位清單顯示組成長條圖、各類別筆數／占全部紀錄比例、前三個已知名稱（占已知名稱）、豐富度、Shannon、最大類別占比與集中度。輪廓色代表最多紀錄的已知來源名稱，不是生態好壞分級。
- **公園組成**：按「資料集＋原始行政區＋正規化公園名」分組，缺名稱另列，不合併跨區同名公園。名稱相同但實為不同公園的來源歧義仍無法完全消除。地圖圓點僅為該組紀錄座標平均點，**不是官方公園位置、範圍或邊界**，亦可由清單查看。行道樹缺公園名稱的紀錄保留在明示缺名組。
- **統計母體**：組成與多樣性使用所選來源、行政區及全站文字搜尋的完整範圍，不隨視野裁切；樹種多選只改空間分布，**不改變組成／多樣性的分母**。全域摘要明示非視野筆數。區里使用空間歸屬，公園分組及分布點位的區篩選使用來源行政區，可能有差異。

名稱只做保守正規化（空白合併、全形 ASCII 與空白轉半形），不做植物同物異名合併、學名推定或混合類群拆株。原始值保留於點位屬性，組成圖每列提示可看正規化前值。空白及明確占位值（-、--、無、不明、未知、未提供、未辨識、其他、unknown、null、n/a、na，不分英文大小寫）歸缺失；「枯木」另視為非物種狀態。其餘為**來源名稱類別**，未經植物分類鑑定；類別豐富度不能逕稱精確生物物種數。

指標：已知名稱筆數 N；S 為已知名稱類別數；pᵢ = 第 i 類筆數 / N；**H′ = −Σ pᵢ ln(pᵢ)**（自然對數，底 e）；最大類別占比為 max(pᵢ)；集中度為 Σpᵢ²。缺失、占位與枯木均不進入這些指標分母，但仍納入總紀錄、完整性與組成圖。無已知名稱時 S=0，H′／最大占比／集中度顯示無法計算，不冒充零多樣性。沒有自訂生態好壞門檻。

本快照 162,369 筆 = 162,344 筆已知來源名稱 + 18 筆缺失 + 7 筆枯木。行道樹缺失 17／枯木 1；公園樹木缺失 1／枯木 6。48 筆不落官方區里（行道樹 21、公園樹木 27），區里組成不強制分派，完整範圍摘要仍保留；公園名稱分組仍保留這些紀錄，並另揭露空間未歸屬筆數。每個單位及總覽皆揭露完整性、指標分母與來源覆蓋限制。

僅涵蓋這兩份調查的可繪製紀錄，不代表全臺北植被；未跨來源去重、未驗證現地存活、調查日期／覆蓋不一致。不推定原生種、樹冠面積或 NDVI，也不從影像產生即時分析。
