# Village tree marker display

Updated2026-10-24 at Newyellow's request: selected-village source tree markers are12px squares rather than8px circles. Species color identity and existing opacity/highlight policies are unchanged; the legend swatches are square too. Marker size is a screen symbol, not canopy size, biological dimensions or ecological quality. Dense overlaps remain available through zoom and the existing same-coordinate record selector.

The existing single Leaflet Canvas renderer is retained, avoiding one DOM element per record. Square paths rotate around their original map coordinate, never the renderer container. A single hovered (or keyboard-previewed) record animates0→45degrees over360ms with standard ease-out-back (coefficient1.70158); leave restores0. Interrupted transitions start from the current angle. A local RAF registry redraws only affected marker bounds and cancels on dataset reset/destroy. Ten-pixel hit/bounds radius covers the rotated square and stroke without changing record coordinates. Existing species matching still highlights same-species peers; only the individual hovered marker rotates. Reduced-motion preference sets orientation immediately. Pointer/click/keyboard record lookup, exact source identities, layers and same-coordinate selectors are preserved.

Validation: two focused pure tests cover square center/side/bounds and360ms overshoot/endpoints/interruption. One actual1100×800 browser check with real village records locates marker pixels and performs unforced pointer hover, settled45degree orientation, leave/reset, reduced-motion immediate orientation and tree click opening the original record panel, with zero JavaScript errors. Required isolated production build passes. No inference, data changes, full regression suite or viewport matrix.
